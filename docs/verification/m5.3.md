# M5.3 — Mock Judge, advisor handoff, and student-content templates

## Scope and interfaces

- `/judge?projectId=…` provides deterministic YSC, NSC and TCAS practice personas. Questions target the linked Idea's latest Evaluation: scores 1–3 first, then 4–6, ascending score with stable axis-order ties; up to three questions. Scores, not potentially inconsistent badge strings, determine selection. Missing/foreign/all-green Evaluation uses explicitly labeled general practice. An Idea changed since Evaluation gets an old-result warning and a re-evaluation link.
- Student answers are saved per Project and persona/question. Unsaved edits disable question, persona and Project switching until saved or cancelled. The rubric fallback offers axis-specific evidence/self-review prompts, **not semantic answer grading, invented scores or a model answer**. This implementation deliberately uses the permitted deterministic/rubric path; no new AI request or gateway credential is needed.
- Proposal workspace now has Proposal, weekly Plan, TCAS, Abstract/Pitch and teacher-review views. Optional role, skills, target field, actual results and learning/limitations are written by the student, saved per Project, and reused across templates and exports. They are never inferred from a planned milestone. Missing fields remain honest prompts; user-entered results are labeled unverified. No real-name, school or contact fields are introduced.
- `assemblePresentationTemplates()` rearranges saved Proposal plus optional student notes. The compact TCAS card excerpts long sections, visibly marking `…`. Abstract has a hard limit of **250 word-like segments**, counted with `Intl.Segmenter('th', {granularity:'word'})`, including headings/status text; this is not a claim that every competition uses that counting convention. Long content is explicitly excerpted, not presented as an AI summary. Pitch intervals are 0:00–0:30, 0:30–1:45, 1:45–3:00, generated from a single numeric source. Actual speaking duration requires a timed rehearsal.
- Existing M4.3 export actions can include or omit templates. Word and Google Docs import use the actual DOCX generator with embedded Sarabun fonts. PDF uses the existing A4 print preview; share links remain read-only compressed document snapshots. Old version-1 share payloads without the optional template fields still decode. Export field allowlists exclude learner/project identity and conversations; free text still requires the learner's privacy review.

## Advisor Review & Sign-off limitations (also visible in both UIs)

1. Student reviews the saved content/privacy disclosure and creates `/advisor-review#…`. The fragment carries a compressed read-only snapshot plus a random request ID and SHA-256 content checksum; it is not sent as an HTTP request path/query.
2. Teacher opens it without login, cannot edit the document, writes a comment and chooses Approve or Request revision. Revision requires a nonblank comment. The teacher **manually sends the generated return code or `/proposal#advisor=…` link back**. Creating it does not send anything to the student.
3. Student pastes the code/link, or opens the return link and explicitly presses import. Import is bound to the selected Project's latest request and exact saved document (including presentation notes). Wrong-Project, replaced-request, changed-content and changed-during-check responses are rejected. The return fragment is cleared after successful import. No global Project completion/safety status is automatically changed.
4. **There is no backend sync, teacher authentication, cryptographic signature, tamper-proof audit log or trusted timestamp. Anyone with the link can create or forge a response.** The checksum prevents accidental stale-document association; it does not prove who approved. The UI calls imported responses unverified and shows old decisions as inapplicable after edits.
5. Approval here is not SRC/IRB approval, permission to conduct a regulated experiment, proof of competition eligibility or acceptance by an official organizer. Real teacher/safety confirmation remains necessary. Share copies are forwardable and cannot be revoked; making a new request only invalidates old return codes in this local workspace.

## Local data lifecycle

- Project-owned auxiliary records use `edtech:judge:<id>`, `edtech:presentation:<id>` and `edtech:advisor:<id>` with encoded IDs, not the core state schema. Malformed auxiliary data is reported/refused, not silently replaced; it cannot trigger a whole-Project migration/reset. Failed saves retain drafts/codes for retry and do not claim persistence.
- Project deletion removes its three auxiliary records while preserving other Projects' records. The existing PDPA namespace wipe also removes all of them. Source integration is covered through the public delete/read interfaces.
- Guest Mode requires no account. No package dependency or environment/secret file was added to the app.
