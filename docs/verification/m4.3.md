# M4.3 export and PWA verification

## Scope and behavior

- `/proposal`: mobile-first export panel for the **saved** Proposal and Plan. Save edits in each tab before exporting; exports do not spend AI quota or require login.
- Word: downloadable `.docx` with all five Proposal sections, student line breaks, weekly Plan, deadline, duration and completion states. Regular/bold Sarabun faces are embedded. Plan begins on a separate page; tables use the available page width.
- PDF: `/print` receives an allowlisted, one-use snapshot through same-tab `sessionStorage`, consumes it immediately and keeps it only in React memory. No document content is sent in the request URL. The print button waits for both actual Thai font faces before opening the browser's **Save as PDF** dialog. Missing fonts fail closed with a Thai error.
- Google Docs: downloads the same Word file, then provides Thai instructions and a Google Drive link for manual upload → Open with Google Docs. The app neither obtains OAuth permissions nor uploads to Google. An authenticated cloud import was **not** performed during verification.
- Read-only `/share#<token>`: gzip + base64url snapshot of document fields only, Zod validation/versioning, 12,000-character token limit and 64,000-byte expanded JSON limit. Decoding stops streaming at the expanded byte cap. Project/Learner IDs, Interview, chat history and arbitrary unknown fields are excluded. Shared documents do not initialize or read the learner store.
- Sharing is an immutable, non-revocable copy, **not encryption or access control**. Anyone with the URL can read/forward it. An explicit review checkbox warns against names, school and other private information in free text. The fragment is not sent to the app server.
- PWA: manifest, 192/512 PNG icons, separate maskable icon, Apple touch icon, theme color, standalone display, optional install prompt and service worker registration. The worker intentionally caches no requests or learner content. **Offline availability is not promised.** Production hosting must use HTTPS (localhost was used here).

### Pagination policy

The short-form Proposal template is designed for one A4 page, with Plan starting separately. The real sample PDF below has exactly one Proposal page plus one Plan page. Arbitrarily long student text is **never truncated or silently shrunk to unreadable text**: it flows onto additional pages. This is disclosed in the print UI. A hard one-page limit for unrestricted input would need a separate accepted shortening/overflow policy; the exporter does not rewrite the student's answers.

### Red → green evidence

- Correcting interrupted-run DOCX fixtures to the canonical domain exposed `proposal.variables?.independent?.trim is not a function`; the generator now handles variable arrays and canonical `week`/`deliverable` fields.
- Font embedding test initially failed on missing `w:embedRegular`; generated Word files now embed regular and bold faces, with Thai language/complex-script declarations.
- Line-break test initially failed on missing `<w:br/>`; multi-line student content now survives Word export.
- Plan-parity test initially failed on missing `ระยะเวลา 4 สัปดาห์`; duration, deadline, progress and a separate Plan page are now exported.
- Share round-trip initially failed because the module did not exist. Successive tests then exposed missing expanded/encoded size guards, a small hostile gzip expanding beyond the budget, and whitespace accepted in malformed tokens. All are now rejected. Thai round-trip, immutability, unknown-field exclusion, malformed schema and unsupported versions pass.

## Production browser checks

Real Chromium against `next start --port 3100`, using **synthetic Thai content only**:

- Returning directly to `/proposal` retains its active project and exposes export controls. Browser testing found and fixed the upstream missing active-project hydration line.
- At **360×800**, document width is exactly 360px (no horizontal overflow); export buttons are 46px or 66px tall. Visual testing also found and fixed white-on-white styling on the PDF button.
- Word click creates a real **100,879-byte** DOCX Blob with the correct MIME type. Its archive contains the Thai title, deadline, completion status and **two `.odttf` embedded fonts**.
- Google Docs click downloads Word and displays the upload/import instructions and `https://drive.google.com/drive/u/0/my-drive` link.
- Share URL for the sample is 660 characters. Only `/share` precedes the fragment. In a cleared browser, Thai Proposal + Plan render with no editable controls; both `localStorage` and `sessionStorage` remain empty. Non-Next resources are local font, icon and manifest assets only.
- `/share#not-a-valid-gzip` shows a Thai error and no document. Direct `/print` without a snapshot shows a Thai error and disables printing.
- `/print` uses an empty query/fragment and consumes the session snapshot. Both `Sarabun Export` faces report `loaded` before the print callback runs.
- Blocking both Sarabun URLs prevents printing and shows the Thai font-load error.
- A real `Page.printToPDF` output is **24,385 bytes**, exactly **2 A4 pages**. PDF inspection finds embedded `Sarabun-Bold` and `Sarabun-Regular`, all five Proposal sections on page 1, Plan on page 2, and no URL headers. The rendered page was visually checked for readable Thai glyphs and clipping.
- At **1280×900**, document width is exactly 1280px; shared document remains read-only with no learner-store writes.
- `Page.getAppManifest`: no parse errors. `Page.getInstallabilityErrors`: **empty array**; install affordance appears and service worker controls the page. Native OS installation was not performed.

## Bounded self-review

Standards/spec self-reviews identified missing DOCX Plan metadata/progress and an over-wide table; both were fixed and verified. Format-specific rendering remains separate (OOXML vs React). The pagination policy above is deliberately explicit for the final reviewer rather than an unconditional claim that arbitrary-length input fits one page. Independent project-wide final review remains after the M5 cards, as requested by the operator. No push or deployment performed.

A separate `npm audit --json` reports 12 dependency advisories (8 moderate, 2 high, 2 critical), including direct `next`, `vitest`, and `zod` entries. No dependency-upgrade remediation is claimed by this export card; final review must assess the audit before release. Neither added `buffer` nor explicit test dependency `jszip` appears in the advisory package list.
